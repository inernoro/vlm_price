# 06｜国内 VLM 实际选型与落地

本章是 [`README-国内版.md`](../README-国内版.md) 的工程补充，聚焦容易在 PoC 与生产之间踩坑的差异。

## 实测边界

国产模型统一使用同一张 1024×1024、1,025,019 bytes 的红色陶瓷杯图片，提示词要求简体中文短 JSON。OpenRouter 用于统一请求格式、记录供应商与 `usage.cost`；它不是境内数据链路。

新增测试模型包括 Qwen3.7 Flash、Qwen3-VL 235B、GLM-4.6V、MiMo V2.5、MiniMax M3、Step 3.7 Flash、Seed 2.1 Turbo 与 Kimi K3，并与主报告已有的 Qwen3-VL 8B/32B、GLM-5V Turbo 合并。

所有产生可见答案的国产模型都正确识别了杯子、红色、陶瓷和数量 1。差异主要体现在内部推理 token、延迟、结构化输出、路由地域和任务定位，而不是这张简单图的准确率。

## 不能把“中国模型”写成“国内链路”

本次实际路由中：Qwen3-VL 235B 由 DeepInfra、MiMo V2.5 由 Parasail、MiniMax M3 由 Venice、Step 3.7 Flash 由 DeepInfra、Kimi K3 由 DigitalOcean 提供。它们是中国团队研发的模型，但本次请求不构成纯国内服务。

若业务要求数据境内，应该：

1. 改用厂商中国区官方 API、国内云市场或专属实例；
2. 在控制台和合同中确认推理与日志地域；
3. 禁用无必要的请求/响应日志并对图片预脱敏；
4. 不使用不明确的自动跨供应商路由；
5. 对更严格场景采用私有化部署。

## 视觉 token 的真实影响

阿里云官方文档给出的 Qwen3.7/Qwen3.6/Qwen3.5/Qwen3-VL 图像 token 估算为：

```text
图像 token ≈ 缩放后高度 × 缩放后宽度 / (32 × 32) + 2
```

1024×1024 在不额外缩放时约为 1026 个视觉 token。项目中 Qwen 系列实际 prompt token 为 1070～1074，包含视觉 token 与短文本提示，和公式吻合。这比“图片 1MB”更接近用户应建立的成本心智。

高分辨率 OCR 并非越高越好。像素越多通常 token、延迟和费用越高；应通过业务验证集找到能看清最小关键文字的像素上限。

## 思考 token 与短任务冲突

| 模型 | 可见输出 | reasoning token | 现象 |
|---|---:|---:|---|
| Qwen3.7 Flash 首轮 | 0 | 300 | `max_tokens=300` 全被推理占用 |
| Qwen3.7 Flash 重试 | 正确 | 541 | 放宽到 800 后才输出 JSON |
| GLM-5V Turbo 首轮 | 0 | 100 | 简单任务仍无可见答案 |
| GLM-5V Turbo 重试 | 正确 | 123 | 需要更大的输出预算 |
| Step 3.7 Flash | 正确 | 195 | 答案很短但推理占主要输出 |
| Seed 2.1 Turbo | 正确 | 145 | 简单任务仍产生推理成本 |
| Kimi K3 | 正确 | 119 | 旗舰模型总成本最高 |

对分类、字段抽取和 OCR 后校验，优先使用 Instruct/非思考模式。只有图表推理、空间关系、复杂页面操作等任务才启用思考，并单独预算 reasoning token。

## 国内厂商路线

### 阿里云百炼 / Qwen

当前官方视觉文档把 Qwen3.7 Plus 作为高能力起点，稳定后可用 Flash 降本；Qwen3.7、Qwen3.6、Qwen3.5 和 Qwen3-VL 支持视觉结构化输出。对于可私有化路线，Qwen3-VL 8B/32B 是更直观的专用 VLM 选择。

### 智谱 / GLM

GLM-4.6V 面向通用视觉推理、长文档和视频，GLM-5V Turbo 更偏多模态 Coding、GUI Agent 与工具执行。简单商品分类优先轻量/免费视觉型号；复杂链路再升级，避免把旗舰 Agent 模型当分类器。

### 火山方舟 / Seed、豆包

火山方舟提供视觉理解模型与企业接入能力，输入中的文字和图片都会转换为 token 计费。生产应在方舟内固定模型与地域，并设置费用告警，而不是依赖聚合器别名。

### Moonshot / Kimi

Kimi K3 是原生视觉旗舰，官方定位长程 coding 与端到端知识工作，1M 上下文能力在长任务中有价值。本次单物品识别约 ¥0.0459/张，说明它不适合作为默认低成本分类器。

### 阶跃星辰

官方视觉模型支持图片/视频、URL/Base64 和多图输入，并明确图片分辨率会影响传输、首字延迟与费用。Model Lab 的实验模型官方不建议生产使用；需要区分体验模型与正式 SLA。

### MiniMax 与 MiMo

聚合器成功让 MiniMax M3 和 MiMo V2.5 接收了图片，但国内官方公开 API 的型号、图片输入字段和商业可用范围可能与聚合器不同。采购或开发前应调用官方模型列表并验证 `supports_image_in`，不能根据 OpenRouter 单次成功直接假定国内直连完全等价。

## API 还是私有化：盈亏平衡方式

不要只比较“元/百万 token”和 GPU 购买价。用下面的完整口径：

```text
API 月成本 = 成功请求 + 失败/重试 + 存储/网络 + 服务套餐

私有化月成本 = GPU/云实例 + 空闲冗余 + 推理框架与量化
             + 运维/监控 + 模型升级 + 容灾 + 电力机房

私有化单张成本 = 私有化月成本 / 当月成功处理图片数
```

流量低、波动大、模型更新频繁时 API 更合理；流量高且稳定、图片敏感、需微调或要求专网时，私有化价值更高。

## 业务评测优先于通用榜单

最低评测集建议 200～1000 张，并按业务风险分层。指标至少包括：

- 图片级准确率与关键类别召回率；
- 字段级精确率/召回率，而不是只看整条 JSON 是否完全匹配；
- JSON Schema 合法率；
- P50/P95 延迟和超时率；
- 首次成功成本与重试后总成本；
- 人工复核率与错误造成的业务损失。

对于证照、医疗、金融、工业质检等高风险场景，必须加入拒答与人工复核机制，不能以本项目的单杯测试作为生产准确性依据。
