# 04｜选型与上线建议

## 直接可用的选择

### 只做商品/物品分类

首选 `qwen/qwen3-vl-32b-instruct`，兜底 `openai/gpt-5.4-nano`。

- Qwen3 VL 32B 本次是最低成功实付价，输出正确且干净。
- GPT-5.4 Nano 速度更快、公开使用热度高，适合做跨供应商兜底。
- 不建议因为“8B 参数更小”就默认它更便宜；本次 Qwen 32B 的目录价和实付价反而低于 8B。

### 识别 + OCR + 复杂字段抽取

从 `openai/gpt-5.4-mini`、`google/gemini-3.7-flash` 开始 A/B。若中文文档和复杂推理是主场景，再加入 `z-ai/glm-5v-turbo`。简单杯子测试不能衡量 OCR，因此必须用真实票据/货架/质检图复测。

### 高风险/复杂多步判断

可以把 `anthropic/claude-sonnet-4.6` 当二审模型，而不是所有图片默认首发。典型路由：便宜模型先做分类与置信检查；字段缺失、规则冲突或低置信样本再升级到 Sonnet。

### 免费试验

免费模型可以用于开发冒烟测试，不能把免费端点当生产 SLA。本次 NVIDIA 免费模型两次均无结果。

## 推荐生产路由

```text
图片预检（格式/尺寸/模糊度）
  → Qwen3 VL 32B：短 JSON 分类
    → 通过 schema + 业务规则：直接入库
    → JSON 无效 / 低置信 / 规则冲突：GPT-5.4 Nano 重试
      → 仍冲突或属于高风险：GPT-5.4 Mini / Claude Sonnet 4.6 二审
      → 无法判断：人工复核
```

这里的“低置信”不能只看模型自报值，应结合：多模型是否一致、类别是否在白名单、关键字段是否齐全、图像质量和历史错误率。

## 上线前最少要做的真实评测

准备 200～1000 张有人工真值的业务图片，至少分层覆盖：

- 正常、低光、模糊、遮挡、旋转、小目标；
- 多物体但只需一个主物体；
- 易混淆类别；
- 中文/英文文字；
- 应拒答或无法判断的图片。

同时记录每个模型的：准确率、关键类别召回率、JSON 合法率、P50/P95 延迟、单张实付价、失败率、重试后总价。价格最低但漏掉关键类别的模型通常最贵。

## 成本保护参数

1. 输出只允许 schema 字段，通常设置 80～200 token；带内部推理的模型需确认推理 token 是否占上限。本次 Gemini/GLM 说明 100 不一定够。
2. 设置 20～30 秒超时；最多重试 1 次，再切兜底模型。
3. 保存 `model`、`provider`、`prompt_tokens`、`completion_tokens`、`usage.cost`、延迟和业务结果。
4. 给单请求设置价格上限或每天预算告警。
5. 对自动路由模型定期检查实际供应商价格。Llama 4 Maverick 本次实付比目录起价估算高 34.4%。
6. 离线批处理可优先查 `:batch` 变体；目录中多家模型的 batch 价约为实时价的 50%，但延迟和完成时效不同。

## API 请求模板（不含 key）

```json
{
  "model": "qwen/qwen3-vl-32b-instruct",
  "messages": [{
    "role": "user",
    "content": [
      {
        "type": "text",
        "text": "Identify the single main object. Return ONLY compact JSON with keys object, color, material, count, confidence."
      },
      {
        "type": "image_url",
        "image_url": {"url": "data:image/png;base64,<BASE64>"}
      }
    ]
  }],
  "temperature": 0,
  "max_tokens": 120
}
```

生产中应从环境变量读取 `OPENROUTER_API_KEY`，不要写进源码、Markdown、日志或前端。
