# 04｜选型与上线建议

## 当前候选池

| 任务层级 | 候选 | 使用条件 |
|---|---|---|
| 低成本分类 | Qwen3.7 Flash、Seed 2.0 Mini、GPT-5.6 Luna | 必须补齐准确率、失败率和 P95 延迟 |
| 通用视觉理解 | Qwen3.7 Plus、Gemini 3.7 Flash、Seed 2.1 Turbo、MiniMax M3、Step 3.7 Flash | 使用业务真值集 A/B |
| 复杂视觉推理 | GLM-5V Turbo、GPT-5.6 Terra、Claude Sonnet 5、Kimi K3 | 只在复杂样本或二审阶段调用 |
| 价格上沿对照 | Claude Opus 5 | 验证高成本是否带来可量化收益 |

`待复测` 只表示目录中存在且支持图片输入，不代表效果结论。

## 最小上线流程

```text
图片预检
  → 低成本模型输出短 JSON
    → schema 与业务规则通过：入库
    → 字段缺失、冲突或低质量：通用模型重试
      → 高风险或复杂样本：高能力模型二审
      → 仍无法判断：人工复核
```

## 业务评测要求

至少准备 200～1000 张人工真值图片，覆盖：正常、低光、模糊、遮挡、旋转、小目标、多物体、易混淆类别、文字和应拒答样本。

统一记录：

- 准确率与关键类别召回率；
- JSON 合法率与拒答质量；
- P50/P95 延迟、失败率和重试率；
- 每 1000 张实付成本及成本分位数；
- 实际供应商与目录价偏差。

## 成本保护

1. 固定图片尺寸、提示词版本和输出 schema。
2. 设置输出 token 上限；带 reasoning 的模型单独监控内部推理。
3. 最多重试一次，再切换兜底或人工。
4. 保存 `usage.cost`，不要只保存 token。
5. 对自动路由设置供应商与价格上限。
6. 每次模型版本升级都重新跑同一真值集。

## API 请求模板

```json
{
  "model": "<CURRENT_MODEL_ID>",
  "messages": [{
    "role": "user",
    "content": [
      {"type": "text", "text": "识别唯一主要物品，只返回指定 JSON。"},
      {"type": "image_url", "image_url": {"url": "data:image/png;base64,<BASE64>"}}
    ]
  }],
  "temperature": 0,
  "max_tokens": 200
}
```

密钥只能从服务端环境变量读取，不得进入源码、Markdown、日志或前端。
