# 02｜交叉验算

## 通用公式

```text
每 1000 张美元 =（输入 token × 输入单价（美元/token）
                 + 输出 token × 输出单价（美元/token）
                 + 按图/按请求附加费）× 1000

每 1000 张人民币 = 每 1000 张美元 × 7.20
N 张预算 = 每 1000 张人民币 × N / 1000
```

OpenRouter 模型目录的 `pricing.prompt` 与 `pricing.completion` 是每个 token 的美元价，页面通常展示为每 1M token。最终以 API 响应中的 `usage.cost` 为准，因为实际供应商可能有折扣或高于目录起价。

## 火山引擎 Seed 复算

Seed 2.1 Turbo 本次由 OpenRouter 的 `Seed` 供应商处理：

```text
1000 张输入费用 = 1384 × $0.50 / 1,000,000 × 1000 = $0.692000
1000 张输出费用 = 171  × $2.50 / 1,000,000 × 1000 = $0.427500
1000 张总费用   = $1.119500
1000 张人民币   = $1.119500 × 7.20 = ¥8.060400
1 万张人民币    = ¥80.604
```

其中输出包含 145 个 reasoning token。若任务只是字段抽取或分类，关闭思考、缩短输出通常更省；如果通过火山方舟直连，单价和计费项应以方舟实际账单重新计算。

## 路由价格为什么会不同

### Llama 4 Maverick

目录起价是输入 $0.20/M、输出 $0.696/M，但本次自动路由到 Novita，账单明细对应 $0.27/M、$0.85/M：

```text
按目录起价估：$0.526760/1000 张
实际账单：    $0.707990/1000 张
差额：        $0.181230/1000 张，实际高约 34.4%
```

### MiniMax M3 与 Kimi K3

这两次实际供应商费用低于目录标价，说明目录价与最终路由价也可能出现折扣。生产环境应记录 `provider` 与 `usage.cost`，不要只保存 token 数。

## 对客报价复算

实测正确结果平均裸成本：

```text
15 个正确结果人民币成本合计 / 15 = ¥9.677086/1000 张
最高成功请求成本（Kimi K3）       = ¥45.882720/1000 张
```

为避免简单提示词低估，将输入按“各模型实测输入 + 500 个文本 token”、输出按 600 个计费 token 重新预算。15 个正确模型的复杂请求平均裸预算为 ¥25.994659/1000 张，最高裸预算为 ¥108.129600/1000 张。

```text
成本保护倍率 = 2 次尝试 × 1.055 支付成本 × 1.20 价格/路由缓冲
             = 2.532

售价倍率 = 成本保护倍率 / (1 - 30% 毛利率)
         = 3.617143

平均法理论售价 = ¥25.994659 × 3.617143 = ¥94.026396/1000 张
最高法理论售价 = ¥108.129600 × 3.617143 = ¥391.120210/1000 张
```

因此平均法向上报价 **¥100/1000 张**，最高法向上报价 **¥400/1000 张**。客户可以自由触发任一模型时必须用最高法；平均法只能用于受控的正确模型组合。税费、人工审核、定制开发、存储和专线不在上述价格内。

## 为什么 1MB 不进入公式

这张 PNG 是 1,025,019 bytes。发送 API 时 base64 会增大传输体积，但供应商返回的计费依据仍是输入/视觉 token，而不是上传字节。相同 1024×1024 图改成更小 JPEG，通常只是带宽下降；除非压缩损伤影响识别，否则 token 成本不会按文件 MB 成比例下降。

真正降本顺序通常是：

1. 选通过业务验证集的低价模型。
2. 把分辨率降到仍能看清目标或关键文字的最低值。
3. 约束输出为短 JSON，简单任务关闭思考。
4. 离线任务使用 batch 价格（若模型与渠道支持）。
5. 设置有限重试与兜底模型，避免无限消耗。
