# 02｜交叉验算

## 两种价格口径

```text
当前目录预算/1000 张
= (统一输入 token × 当前输入单价
 + 统一输出 token × 当前输出单价) × 1000

实验室实付/1000 张
= 单次 API 响应 usage.cost × 1000
```

目录预算用于横向比较；实验室实付用于证明真实成本。两者不能合并成一个“精确价格”。

## 统一目录预算

自动报价采用：每张 1500 输入 token、200 输出 token、1000 张、$1=¥7.20。

以 OpenRouter 当前目录中的 GPT-5.6 Luna 为例：

```text
输入：1500 × $0.10 / 1,000,000 × 1000 = $0.15
输出： 200 × $0.60 / 1,000,000 × 1000 = $0.12
合计：$0.27/1000 张 = ¥1.944/1000 张
```

这是统一预算，不是 GPT-5.6 Luna 的实验实付。不同模型的视觉 token 规则不同，必须同图调用后才能得到可比的 `usage.cost`。

## 实验实付示例

### Qwen3 VL 32B

```text
1070 × $0.104 / 1,000,000
+ 36 × $0.416 / 1,000,000
= $0.000126256/次
= $0.126256/1000 张
= ¥0.909043/1000 张
```

### Seed 2.1 Turbo

```text
1384 × $0.50 / 1,000,000 × 1000 = $0.692000
 171 × $2.50 / 1,000,000 × 1000 = $0.427500
合计                                 = $1.119500/1000 张
人民币                               = ¥8.060400/1000 张
```

输出 171 token 中包含 145 reasoning token。该结果证明本次账单构成，不证明 Seed 在其他任务上的性价比排名。

## 路由浮动示例

Llama 4 Maverick 的目录起价与实际 Novita 路由价不同：

```text
目录起价估算：$0.526760/1000 张
实际账单：    $0.707990/1000 张
差额：        $0.181230/1000 张，约 +34.4%
```

因此生产系统至少保存：`model`、`provider`、输入/输出 token、`usage.cost`、延迟、重试次数和业务结果。

## 价格为什么浮动

| 因素 | 对成本的影响 |
|---|---|
| 视觉 token 规则 | 相同分辨率在不同模型上可能产生不同输入 token |
| 输出长度 | OCR 全文、长描述和 JSON 解释显著增加输出费 |
| reasoning token | 短答案仍可能产生大量内部推理 |
| 自动路由 | 实际供应商可能高于或低于目录起价 |
| 重试 | 失败或截断请求也可能产生账单 |
| 缓存与 batch | 命中缓存或批处理可能降低价格 |
| 直连渠道 | 官方直连价可能与聚合渠道不同 |
